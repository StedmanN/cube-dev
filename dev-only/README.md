# Dev-only authentication

This folder contains development login code. Do not copy it to the production app.
Private account configuration lives separately in `.dev-auth/`, which is ignored
by Git and must also be excluded from production transfers and deployment bundles.

## Files

- `auth/users.mjs`: verifies passwords against `.dev-auth/users.json`.
- `auth/session.ts`: creates, verifies, and clears signed login cookies.
- `auth/actions.ts`: login/logout Server Actions and sign-in attempt limits.
- `scripts/hash-password.mjs`: interactive password hash generator.

From the app root, generate a password hash with:

```sh
node dev-only/scripts/hash-password.mjs
```

Private files remain in their original locations:

```text
.dev-auth/users.json
.dev-auth/session-secret
```

## Current integration status

These modules have only been reorganized. The login page and shared session
handler have not been switched to password authentication. The existing automatic
local Developer session remains enabled until the remaining guided edits are made.
No credentials have been moved, read, printed, or regenerated by this reorganization.

For the remaining guided edits, use these imports:

```ts
import { devLogin, devLogout } from "@/dev-only/auth/actions";
import { getDevSession } from "@/dev-only/auth/session";
```

## Production boundary

The folder name does not automatically exclude code from a build or deployment.
Exclude both `dev-only/` and `.dev-auth/` when transferring files to production.
Any future imports in shared files such as `app/page.tsx` or `lib/app-session.ts`
must also be omitted or replaced with production authentication during promotion.
Keep production CAC/Cognito authentication and production database configuration.
A development-specific commit or branch can provide an additional boundary when
this checkout is placed under Git version control.
